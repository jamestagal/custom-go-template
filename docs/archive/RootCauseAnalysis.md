
Here's a breakdown of why the "undefined expression" errors are happening and how to fix it, referencing the *new* codebase structure:

**Root Cause Analysis:**

1.  **Incomplete Data Scope Generation:** The `transformer.TransformAST` function correctly initializes a `dataScope` using props and the *entrypoint's* fence data (`CollectFenceData`). However, when it encounters a component node (e.g., `<Header>`, `<ProductCard>`), the current `transformer.transformComponent` function **does not load, parse, and extract the data/functions defined in the *component's own fence***. It only creates a placeholder element (`<div x-component="..." data-prop-* ...>`) and adds the *names* of the passed props (like `user`, `formatPrice`) to the *parent's* `dataScope` via `extractVariablesFromExpr`.
2.  **Missing Component Logic:** Consequently, functions like `formatPrice` (defined in `ProductCard.html`'s fence) or `getGreeting` (defined in `Header.html`'s fence) are never added to the final `dataScope` that gets rendered into the main `x-data` attribute on the root element (e.g., the `<body>` or a wrapper `<div>`).
3.  **Alpine.js Runtime:** When the browser loads the page, Alpine initializes with the main `x-data` scope generated by `alpineDataFormatter`. When it encounters an expression like `<span x-text="formatPrice(product.price)">` (which originates from the *rendered* `ProductCard`), it looks for `formatPrice` within its *current scope* (the main `x-data`). Since `formatPrice` was never added to that main scope, Alpine throws the "formatPrice is not defined" error. The same applies to all other undefined variables/functions that were defined within component fences.
4.  **Component Placeholders:** The transformation currently replaces component tags (`<Header />`) with simple placeholders (`<div x-component="Header" ...>`). It doesn't actually *inline* the transformed content of the component *during the AST transformation phase*. The recursive rendering approach in `renderer/component.go` was removed (which is good for AST integrity), but it hasn't been replaced by recursive *transformation*.

**Solution: Implement Recursive Component Transformation**

The fundamental fix is to make the AST transformation process truly recursive for components.

**Steps:**

1.  **Component Registry/Loading:** Ensure the `transformer` has access to the parsed ASTs of all potential components. The `RegisterComponent` function in `cmd/server/main.go` seems to do this pre-parsing, which is a good start. The `transformer` needs to reliably retrieve these registered templates.

2.  **Modify `transformer.transformComponent`:** This function needs a major overhaul. Instead of returning a simple placeholder `div`, it should perform the full transformation of the component it represents.

    *   **Input:** `node *ast.ComponentNode`, `parentDataScope map[string]any`
    *   **Logic:**
        *   Look up the registered `ComponentTemplate` for `node.Name` using `GetComponentTemplate(node.Name)`. If not found, return an error node or placeholder.
        *   Create a **new, isolated `componentDataScope`** for this specific instance.
        *   **Process Component Fence:** Extract variables and *default* prop values from the `ComponentTemplate.Template`'s `FenceSection` and add them to `componentDataScope`. Crucially, **copy function definitions** (as strings) from the fence into this scope.
        *   **Resolve Passed Props:** Iterate through `node.Props` (the props passed in the parent template like `user={currentUser}`).
            *   For each prop, evaluate its value *against the `parentDataScope`*.
                *   If static (`prop.IsDynamic == false`), parse the literal value.
                *   If dynamic (`prop.IsDynamic == true`), the `prop.Value` is an expression name (e.g., `currentUser`). Get the *actual value* of `currentUser` from `parentDataScope`.
            *   **Override/Set Prop in `componentDataScope`:** Add the resolved prop name and its *actual value* (obtained from the parent or the literal) to the `componentDataScope`, potentially overwriting the default value from the component's fence.
        *   **Transform Component Body:** Call `transformNodes` recursively on the `ComponentTemplate.Template.RootNodes` (the actual HTML part of the component), passing the newly created `componentDataScope`. Let this return `transformedChildNodes`.
        *   **Generate Component Root with `x-data`:** Determine the root element of the `transformedChildNodes`. If it's a single element, add an `x-data` attribute to it using `alpineDataFormatter(componentDataScope)`. If there are multiple root nodes, wrap them in a `div` with the `x-data` attribute.
        *   **Return Transformed Nodes:** Return the resulting node(s) (the component's transformed root element(s) with their own `x-data`).

3.  **Modify `transformer.transformNodes`:** When iterating, if it encounters the result of `transformComponent` (which will now be the actual transformed component nodes, potentially wrapped), append those nodes to `transformedNodes`.

4.  **Fix `alpineDataFormatter` (Crucial):** Implement the direct JS object string generation as described in the previous answer. Ensure it correctly handles function strings (outputting them without quotes) and other Go types.

func collectComponentFenceData(fence *ast.FenceSection, scope map[string]any) {
     // Similar to CollectFenceData but ensures functions are stored as strings
     // Process variables
     for _, variable := range fence.Variables {
         // Basic parsing - refine as needed
         scope[variable.Name] = parseValue(variable.Value) // Use the parser helper
     }

              }

     }

// Helper function to extract functions as strings from fence content
func extractFunctionsFromFence(rawContent string, scope map[string]any) {
    // Regex to find function definitions (adjust as needed for your syntax)
    functionRegex := regexp.MustCompile(`(?:function\s+([a-zA-Z_$][a-zA-Z0-9_$]*)\s*\([^)]*\)\s*{[^}]*})|(?:(?:let|const|var)\s+([a-zA-Z_$][a-zA-Z0-9_$]*)\s*=\s*(?:function\([^)]*\)\s*{[^}]*}|\([^)]*\)\s*=>\s*{[^}]*}))`)
    
    matches := functionRegex.FindAllStringSubmatch(rawContent, -1)
    
    for _, match := range matches {
        var fnName string
        var fnBody string
        
        if match[1] != "" { // Matched: function name() { ... }
            fnName = match[1]
            fnBody = match[0]
        } else if match[2] != "" { // Matched: const name = function() { ... } or () => { ... }
            fnName = match[2]
            // Extract the function part after '='
            eqIndex := strings.Index(match[0], "=")
            if eqIndex != -1 {
                 fnBody = strings.TrimSpace(match[0][eqIndex+1:])
            } else {
                 fnBody = match[0] // Fallback
            }
        }
        
        if fnName != "" {
            log.Printf("  Extracted function '%s' from component fence", fnName)
            scope[fnName] = fnBody // Store the function definition as a string
        }
    }
}

func resolvePropValue(prop ast.ComponentProp, parentScope map[string]any) any {
    if prop.IsDynamic {
        // Value is an expression referencing parent scope
        expr := strings.TrimSpace(prop.Value)
        // Simple case: direct variable reference
        if val, ok := parentScope[expr]; ok {
            return val // Return the actual value from parent
        }
        // More complex expression - keep the expression string itself
        // Alpine will evaluate it using the parent scope at runtime
        // (This requires careful handling of how component data is finally structured)
        // For now, let's return the expression string, assuming the component x-data will reference parent scope correctly
        // A better approach might involve more complex scope merging or Alpine's prop binding features.
        log.Printf("  Prop '%s' is dynamic expression '%s', passing expression string.", prop.Name, expr)
        return expr
    } else if prop.IsShorthand {
         // Shorthand {prop} -> reference parent variable
          if val, ok := parentScope[prop.Name]; ok {
             return val
          }
          log.Printf("  Warning: Shorthand prop '%s' not found in parent scope.", prop.Name)
          return nil
    } else {
        // Static value
        return parseValue(prop.Value) // Use the same parser helper
    }
}

// Helper to filter out fence node
func filterOutFence(nodes []ast.Node) []ast.Node {
     var filtered []ast.Node
     for _, n := range nodes {
          if _, isFence := n.(*ast.FenceSection); !isFence {
               filtered = append(filtered, n)
          }
     }
     return filtered
}


// Helper to parse simple values (reuse from cmd/server/main.go or move to utils)
func parseValue(value string) interface{} {
	value = strings.TrimSpace(value)
	if value == "true" { return true }
	if value == "false" { return false }
	if value == "null" { return nil }
	// Basic number check (refine if needed)
	if num, err := strconv.ParseFloat(value, 64); err == nil { return num }
	// String check (remove quotes)
	if (strings.HasPrefix(value, `"`) && strings.HasSuffix(value, `"`)) ||
	   (strings.HasPrefix(value, `'`) && strings.HasSuffix(value, `'`)) {
		return value[1 : len(value)-1]
	}
    // If it looks like an expression or object/array literal, return as string for Alpine
    if strings.ContainsAny(value, "{[().+*/-?=") || isValidIdentifier(value) {
         return value
    }
	// Default to the raw string if unsure
	return value
}
